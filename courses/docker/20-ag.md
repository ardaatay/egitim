# Ağ: sürücüler, bridge, port yayınlama, konteynerler arası DNS

Docker ağının çoğu sorunu üç yanlış anlamadan çıkar: "konteynerler birbirini adıyla bulur" (sadece belirli ağlarda), "`-p` ile portu açtım, güvenlik duvarım korur" (çoğu zaman korumaz) ve "uygulama `localhost`'u dinliyor, olur" (konteynerde olmaz). Bu derste Docker'ın ağ modelini çekirdek seviyesinden başlayarak kuruyoruz.

## Sürücü (driver) ve eklenti sistemi

Docker ağ ve depolamayı **sürücüler** üzerinden yönetir. Her ağ bir sürücüyle oluşturulur ve sürücü, o ağın çekirdekte nasıl kurulacağını belirler. Üçüncü taraf sürücüler eklenti (plugin) olarak yüklenebilir. Volume'ler için de aynı yapı vardır (depolama dersi).

| Sürücü | Ne yapar | Ne zaman |
|---|---|---|
| `bridge` | Host üzerinde sanal bir köprü (switch). Konteynerler özel bir alt ağda, dışarıya NAT ile çıkar | **Varsayılan**, tek sunucu |
| `host` | Ağ namespace'i yok: konteyner host'un ağını doğrudan kullanır | Yüksek performans, çok sayıda port (port yayınlamaya gerek yok) |
| `none` | Sadece loopback | Ağa hiç ihtiyacı olmayan işler (hesaplama, dosya işleme) |
| `overlay` | Birden fazla sunucuya yayılan sanal ağ (VXLAN) | Swarm (orkestrasyon bölümü) |
| `macvlan` / `ipvlan` | Konteynere fiziksel ağdan doğrudan IP/MAC | Konteynerin ağda ayrı bir cihaz gibi görünmesi gereken eski sistemler |

```bash
docker network ls
docker network inspect bridge --format '{{range .IPAM.Config}}{{.Subnet}} gw={{.Gateway}}{{end}}'
ip addr show docker0
```

Docker kurulduğunda üç ağ hazır gelir: `bridge` (sürücüsü de bridge), `host` ve `none`. `docker0` arabirimi, varsayılan bridge ağının host tarafındaki köprüsüdür.

## Bridge ağı çekirdekte nasıl kurulur?

Bir konteyner bridge ağına bağlandığında Docker:

1. Bir **veth çifti** oluşturur: iki ucu birbirine bağlı sanal bir kablo.
2. Bir ucu konteynerin ağ namespace'ine koyar ve `eth0` adını verir.
3. Diğer ucu host'ta bırakıp köprüye (`docker0`) takar.
4. Konteynere alt ağdan bir IP verir, varsayılan rotayı köprünün IP'si yapar.
5. Dışarı çıkış için NAT (masquerade) kuralı ekler.

```bash
docker run -d --name a1 alpine sleep 3600
docker exec a1 ip addr show eth0
docker exec a1 ip route
ip link show master docker0
docker exec a1 ping -c 2 8.8.8.8
```

Host'ta `vethXXXX` adlı bir arabirim gördün: konteynerin `eth0`'ının öbür ucu. Konteyner köprü üzerinden host'a, host'un NAT kuralıyla internete çıkıyor.

## Varsayılan bridge ile kendi ağın arasındaki fark

Varsayılan `bridge` ağındaki iki konteyner birbirine **IP ile** ulaşabilir ama **adla** ulaşamaz:

```bash
docker run -d --name a2 alpine sleep 3600
docker exec a2 ping -c 1 a1
A1_IP=$(docker inspect -f '{{.NetworkSettings.IPAddress}}' a1)
docker exec a2 ping -c 1 $A1_IP
```

Kendi oluşturduğun (user-defined) bridge ağında ise Docker'ın **gömülü DNS sunucusu** devreye girer:

```bash
docker network create uygulama
docker run -d --name db --network uygulama alpine sleep 3600
docker run -d --name api --network uygulama alpine sleep 3600
docker exec api ping -c 1 db
docker exec api cat /etc/resolv.conf
docker exec api nslookup db 2>/dev/null | tail -3
```

`/etc/resolv.conf` içinde `nameserver 127.0.0.11`: Docker'ın her konteynerin ağ namespace'ine yerleştirdiği DNS sunucusu. Konteyner adlarını (ve takma adları) aynı ağdaki IP'lere çözer, diğer adları host'un DNS sunucularına iletir.

| | Varsayılan `bridge` | Kendi bridge ağın |
|---|---|---|
| Adla erişim (DNS) | Yok (eski `--link` gerekir) | **Var** |
| İzolasyon | Bütün konteynerler aynı ağda | Sadece aynı ağdakiler birbirini görür |
| Çalışırken bağla/ayır | Hayır | `docker network connect/disconnect` |
| Alt ağ ve ayarlar | Sabit (`daemon.json`) | Ağ başına (`--subnet`, `--internal`) |

Kural: **Her uygulama için kendi ağını oluştur**, varsayılan bridge'i kullanma. Compose bunu otomatik yapar.

### Ağ ile izolasyon

Farklı ağlardaki konteynerler birbirine ulaşamaz:

```bash
docker network create baska
docker run -d --name yabanci --network baska alpine sleep 3600
docker exec yabanci ping -c 1 -W 2 db || echo "db'ye erişilemiyor"
docker network connect uygulama yabanci
docker exec yabanci ping -c 1 db
docker network disconnect uygulama yabanci
```

Tipik bir düzen: `frontend` ağında nginx ve api, `backend` ağında api ve veritabanı. api iki ağa da bağlı. nginx veritabanına hiç ulaşamaz. Dışarıya hiç çıkmaması gereken bir ağ için `docker network create --internal backend`: o ağdaki konteynerlerin NAT ile internete çıkışı da kapanır.

### Takma adlar

Aynı ağda birden fazla konteyner aynı takma adı alabilir. DNS sorgusu hepsinin IP'lerini döner (basit bir yük dağıtımı):

```bash
docker run -d --name api2 --network uygulama --network-alias api-havuzu alpine sleep 3600
docker run -d --name api3 --network uygulama --network-alias api-havuzu alpine sleep 3600
docker exec db nslookup api-havuzu 2>/dev/null | grep -A3 Name
```

## Port yayınlama

Bridge ağındaki bir konteynere dışarıdan erişmek için portu **yayınlarsın**:

```bash
docker run -d --name web -p 8080:80 nginx:1.27-alpine
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080
docker port web
ss -tlnp | grep 8080
```

| Yazım | Anlamı |
|---|---|
| `-p 8080:80` | Host'un **bütün** arabirimlerindeki 8080 → konteyner 80 |
| `-p 127.0.0.1:8080:80` | Sadece host'un loopback'i (dışarıdan erişilemez) |
| `-p 10.0.0.5:8080:80` | Sadece o IP |
| `-p 80` | Host'ta rastgele boş bir port → konteyner 80 (`docker port` ile öğren) |
| `-P` | İmajdaki bütün `EXPOSE` portlarını rastgele portlara yayınla |
| `-p 5353:53/udp` | UDP |

`ss` çıktısında 8080'i `docker-proxy` dinliyor. Gerçek yönlendirme ise çekirdekte **NAT kurallarıyla** yapılır:

```bash
iptables -t nat -L DOCKER -n 2>/dev/null || nft list ruleset | grep -A3 -i dnat | head
```

### Docker ve güvenlik duvarı

Bu, üretimde en sık yapılan güvenlik hatalarından biridir. Docker, yayınlanan portlar için **kendi iptables kurallarını, host güvenlik duvarının kurallarından önce** ekler. Bu yüzden `ufw deny 8080` yazmak, Docker'ın yayınladığı 8080'i **engellemez**.

Sonuç: `docker run -p 5432:5432 postgres` yazdıysan veritabanın, `ufw` "kapalı" dese bile **internete açıktır**.

Doğru yaklaşımlar:

- Dışarıya açılması gerekmeyen her şeyi **`127.0.0.1:`** ile yayınla: `-p 127.0.0.1:5432:5432`. Önündeki nginx ya da bir SSH tüneli üzerinden eriş.
- Daha iyisi: Veritabanını **hiç yayınlama**. Aynı Docker ağındaki uygulama ona adıyla (`db:5432`) ulaşır.
- Kural koyman gerekiyorsa Docker'ın bu amaçla ayırdığı `DOCKER-USER` zincirine ekle (Docker o zinciri kendi kurallarından önce değerlendirir), ya da bulut sağlayıcısının güvenlik duvarını kullan.

```bash
docker run -d --name db-acik -p 5432:5432 -e POSTGRES_PASSWORD=x postgres:16-alpine
docker run -d --name db-yerel -p 127.0.0.1:5433:5432 -e POSTGRES_PASSWORD=x postgres:16-alpine
ss -tlnp | grep -E '5432|5433'
docker rm -f db-acik db-yerel
```

`0.0.0.0:5432` dışarıya açık, `127.0.0.1:5433` sadece yerel.

## "localhost" tuzakları

Konteynerin ağ namespace'i kendine ait olduğu için `localhost` bağlama göre farklı şeyler ifade eder:

**1. Konteynerdeki uygulama `127.0.0.1`'i dinliyorsa, `-p` ile yayınlasan bile erişilemez.**

```bash
docker run -d --name yanlis -p 8081:8000 python:3.12-alpine python -m http.server 8000 --bind 127.0.0.1
docker run -d --name dogru  -p 8082:8000 python:3.12-alpine python -m http.server 8000 --bind 0.0.0.0
sleep 2
curl -s -o /dev/null -w 'yanlis: %{http_code}\n' localhost:8081 || echo "yanlis: bağlantı başarısız"
curl -s -o /dev/null -w 'dogru: %{http_code}\n' localhost:8082
docker rm -f yanlis dogru
```

NAT, paketi konteynerin `eth0` adresine yönlendirir. Uygulama sadece konteynerin kendi loopback'ini dinlediği için cevap vermez. **Konteynerde uygulamalar `0.0.0.0` dinlemelidir.** Dış erişimi kısıtlamak `-p 127.0.0.1:` ile host tarafında yapılır. (Linux kursunda "uygulama `127.0.0.1` dinlesin" demiştik. O kural konteynersiz kurulum içindi.)

**2. Konteynerin içinden `localhost:5432` yazmak, host'taki veritabanına değil konteynerin kendisine gider.** Host'taki bir servise ulaşmak için:

```bash
docker run --rm --add-host=host.docker.internal:host-gateway alpine ping -c 1 host.docker.internal
```

`host-gateway` köprünün host tarafındaki IP'sine çözülür. Docker Desktop'ta `host.docker.internal` hazır gelir. Linux'ta bu satır gerekir. Host'taki servisin de o arabirimi (ya da `0.0.0.0`) dinlemesi gerekir.

## host ve none ağları

```bash
docker run -d --name hostnet --network host nginx:1.27-alpine
curl -s -o /dev/null -w '%{http_code}\n' localhost:80
docker exec hostnet ip addr | grep -E '^[0-9]+:' | head -5
docker rm -f hostnet
docker run --rm --network none alpine ip addr
```

- `--network host`: Konteyner host'un ağ arabirimlerini doğrudan görür, port yayınlamaya gerek yoktur ve NAT maliyeti yoktur. Bedeli: ağ izolasyonu yok, iki konteyner aynı portu dinleyemez. Docker Desktop'ta (Mac/Windows) davranışı farklıdır, çünkü "host" oradaki Linux VM'idir.
- `--network none`: Sadece `lo`. Dışarıyla hiçbir iletişim yok.

Bir de **başka bir konteynerin ağını paylaşmak** var: `--network container:api`. İki konteyner aynı ağ namespace'ini paylaşır ve birbirine `localhost` üzerinden ulaşır. Kubernetes'teki **pod** kavramı tam olarak budur. Teşhis için de çok kullanışlıdır: içinde araç olmayan bir konteynerin ağına araç dolu bir konteynerle katılmak:

```bash
docker run -d --name minimal --network uygulama nginx:1.27-alpine
docker run --rm --network container:minimal nicolaka/netshoot ss -tlnp
```

`nicolaka/netshoot` içinde `curl`, `dig`, `tcpdump`, `ss`, `iperf` gibi yüzlerce ağ aracı bulunan bir teşhis imajıdır.

## Alıştırma (lab'da)

Şu düzeni kur:

- `on` ve `arka` adında iki ağ. `arka` dışarıya çıkışı olmayan (internal) bir ağ olsun.
- `nginx` konteyneri sadece `on` ağında, host'un `127.0.0.1:8090` portuna yayınlanmış.
- `api` konteyneri (`alpine sleep 3600` yeterli) her iki ağda.
- `db` konteyneri sadece `arka` ağında.

Doğrula: `nginx` → `api` erişilebilir, `nginx` → `db` erişilemez, `api` → `db` erişilebilir, `db` internete çıkamaz.

<details><summary>Çözüm</summary>

```bash
docker network create on
docker network create --internal arka
docker run -d --name nginx --network on -p 127.0.0.1:8090:80 nginx:1.27-alpine
docker run -d --name api --network on alpine sleep 3600
docker network connect arka api
docker run -d --name db --network arka alpine sleep 3600

docker exec nginx ping -c 1 -W 2 api && echo "nginx -> api OK"
docker exec nginx ping -c 1 -W 2 db || echo "nginx -> db erişilemez (beklenen)"
docker exec api ping -c 1 -W 2 db && echo "api -> db OK"
docker exec db ping -c 1 -W 2 8.8.8.8 || echo "db internete çıkamaz (beklenen)"
ss -tlnp | grep 8090

docker rm -f nginx api db; docker network rm on arka
```

`nginx` imajında `ping` BusyBox'tan gelir. `ss` çıktısında 8090'ın sadece `127.0.0.1`'e bağlı olduğunu görürsün.

</details>

## Özet

- Sürücüler: `bridge` (varsayılan), `host`, `none`, `overlay` (Swarm), `macvlan`.
- Bridge = veth çifti + köprü + NAT. Konteynerin `eth0`'ı, kendi IP'si, kendi `localhost`'u.
- Her uygulama için `docker network create`: ad çözümleme (127.0.0.11) ve izolasyon. `--internal` ile dışa kapalı ağ.
- `-p host:konteyner`, dışa açılmaması gerekenler için `-p 127.0.0.1:...`. **Docker, ufw'yi atlar.**
- Konteynerde uygulama `0.0.0.0` dinler. Host'a erişim `host.docker.internal` + `host-gateway`.
- Teşhis: `--network container:X nicolaka/netshoot`.
